# SSC 并发启用修复

平台包固定使用 libssc v0.4.4 的提交
`0cf77b93b55752da34dca2dcecc06fca8665184b`，应用同目录补丁，在 Arch／Armada
各自的构建根中编译。`scripts/ssc/install-rootfs.sh` 安装原始传感器资产后，
`install-caihong-ssc-stage.sh` 再安装修复版库，避免原始资产覆盖修复。

原实现把启用完成通知的处理器编号存在整个传感器对象中。两个调用并发启用时，
后一次覆盖前一次编号；前一个回调断开了错误的处理器，并释放自己的上下文，
下一条报告仍会调用已经释放的上下文。补丁改为每项操作各自保存处理器编号。

构建会执行以下无硬件依赖的回归后才安装库：

- 测量通知先到：256 轮、每轮两个并发启用，检查两个回调均完成且没有残留处理器。
- 配置通知先到：同样执行 256 轮，并追加报告以检查释放后的上下文不会再次使用。
- 环境光正值变为 0 lux 时应正常上报，负数仍丢弃；关灯后的 0 lux 不是故障。

产物使用原来的私有库路径 `/usr/local/lib/caihong-ssc/libssc.so.2`，不替换系统库。
版本、源码提交及补丁哈希记录在 `/usr/share/caihong/ssc-build-info`。
现有传感器校准和注册表不改写。源码回归不替代实际设备的并发采样、休眠唤醒验证。
